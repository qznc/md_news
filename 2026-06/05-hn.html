The AI Effect: How AI Is Reshaping Open Source Development and Code Contributions

The Ladybird browser project has decided to stop accepting public pull requests, citing the rise of AI-generated code as a key reason for this shift, marking a notable change in how open source projects manage contributions and trust.

For decades, open source projects like Ladybird have relied on public contributions as a way to identify and build trust with new contributors. A well-crafted pull request used to signal effort, commitment, and good intent, serving as a proxy for a contributor’s reliability. However, AI tools have disrupted this dynamic. As Andreas Kling, a maintainer of Ladybird, explains, AI-generated patches now make it harder to determine the true intent or effort behind a submission. A substantial patch no longer guarantees substantial human effort, and the assumption that effort equates to trustworthiness no longer holds. This shift is particularly critical for a browser project, where even a single vulnerability can have severe consequences.

The Ladybird team’s decision highlights a broader concern in open source: accountability. Every piece of code integrated into a project becomes the responsibility of its maintainers. It must align with the project’s architecture, endure future changes, and be understood by the team. As Kling puts it, the question is not whether the code was written by a human or AI, but who will take responsibility for it once it is part of the project. For Ladybird, this means restricting code submissions to maintainers, ensuring that those who introduce changes are also those who can answer for them. While the project remains open source, contributions like bug reports, testing, and discussions are still encouraged, underscoring that open source can thrive in forms beyond direct code submissions.

In contrast, some developers are embracing the efficiencies AI brings to documentation. Mark Dominus shares his experience of using AI to generate project summaries and handoff documents, which he then reviews, edits, and commits to the repository. This practice not only streamlines the documentation process but also ensures that future contributors—whether human or AI—can benefit from the structured insights left behind. As Dominus notes, the key is treating AI-generated content with the same level of oversight as human work. The documentation becomes a form of collaborative continuity, bridging knowledge gaps and leaving a trail for others to follow.

These developments point to a deeper change in how open source is evolving. AI is not just a tool for writing code faster but is altering the very mechanisms of trust and contribution. It challenges the notion that effort and intent can be inferred from code alone, forcing maintainers to rethink how they evaluate and integrate contributions. At the same time, AI can free up human contributors to focus on higher-level thinking, such as design, oversight, and documentation, rather than getting bogged down in the minutiae. The balance between open collaboration and safeguarding the integrity of a project seems to be shifting toward a more curated, maintainer-driven model, at least for high-stakes projects like browsers.
