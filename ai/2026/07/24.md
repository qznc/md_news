# Runtime Observability and Mechanistic Tools Reveal Limits of Steering Large Language Models

Mechanistic interpretability aims to reverse‑engineer the internal computations of transformer models.  
Recent work shifts focus from static circuit analysis to dynamic runtime observability.  
This shift exposes a gap between observing model dynamics and reliably controlling them.

The attractor‑mapping framework treats generation as a trajectory through hidden‑state space.  
It extracts runtime metrics such as hidden‑state norm, cosine similarity, curvature, and output entropy for every token.  
These metrics are clustered into dynamical regions called attractors.  
Trajectories repeatedly revisit a small set of regions rather than wandering randomly.  
Segmentation detects phase changes in the trajectory without assuming fixed reasoning stages.  
Interventions such as orthogonal rotations and trajectory matching can alter the path.  
However, changing the trajectory does not reliably improve reasoning accuracy.  
The author concludes that observation is far easier than control.  
The attractor map serves as a runtime observability tool, not proof of cognitive states.

A complementary effort packages interpretability workflows into a local desktop application.  
The tool provides token‑level telemetry, logit‑lens inspection, hidden‑state projections, attention visualization, and causal interventions.  
It runs on consumer GPUs with open‑weight models and separates measured data from derived views.  
The developer seeks feedback on scientific validity rather than aesthetics.

Foundational circuit analysis shows that small attention‑only transformers implement interpretable algorithms.  
Induction heads in two‑layer models explain in‑context learning through attention‑head composition.  
The residual stream decomposes into communication channels used by embeddings, heads, and MLPs.  
These insights scale partially to larger models but full reverse engineering remains distant.  
Source: [A Mathematical Framework for Transformer Circuits](https://transformer-circuits.pub/2021/framework/index.html).

Pros of runtime observability include real‑time insight into generation dynamics, architecture‑agnostic metrics, and automatic segmentation of reasoning phases.  
Tools like the desktop observatory lower the barrier to causal experimentation.  
Cons include the lack of proven correspondence between dynamical clusters and semantic operations.  
Interventions that modify trajectories fail to guarantee correct outputs.  
Visualizations such as 3D trajectories risk being compelling but uninformative.  
The field lacks standardized metadata for reproducibility across tools.

The emerging conclusion is that mechanistic interpretability has matured into a discipline of measurement.  
Runtime observability provides a reproducible lens on model behavior.  
Reliable steering remains an open problem requiring deeper causal understanding.  
Future work must bridge the gap between dynamical description and semantic control.
